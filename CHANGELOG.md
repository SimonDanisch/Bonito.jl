# Changelog

All notable changes to Bonito.jl are documented here. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project follows [semantic versioning](https://semver.org/).

## [Unreleased]

### Added

- `HierarchicalMenu` widget with `HierarchicalMenuItem` and `HierarchicalSubMenu` for nested, collapsible menus. The clicked leaf's value is pushed to `menu.selected_value`. Themed via the `--bonito-widget-*` CSS variables (dark-mode aware) and styleable through the `style` keyword.
- `Bonito.Sessions.on_free(session_id, f)` (JS): runs `f` once when the session is freed, for what a session's code built that Bonito does not track (an editor, a WebGL context). JS `Observable.off(callback)` removes a listener `on` added.
- `Bonito.on_refused(handler)` (JS): called when the server turns a payload request away (a redirect to a login page, 401, 403). The payload is fetched again once the promise `handler` returns resolves, so an app can wait for its login to come back.
- `Server(...; gate)`: a gate every request passes before any route, websocket upgrades included (`HTTPServer.gate_request`), and every response after it (`HTTPServer.gate_response`). A login check there covers every route, including the asset and websocket routes Bonito registers itself.
- A message from a page that the server takes half a second or more to handle is logged with its type, the page and, for an observable update, where its listeners are defined. A page's messages are handled one after another, so such a message holds up everything after it, the page's pings included.

### Fixed

- Proxied apps reuse the host's Bonito runtime, so a relative asset URL or hostname alias cannot load a second runtime and leave the host unready.
- The precompile serving workload waits for session readiness instead of assuming initialization finishes within 200 ms.
- Pin the browser queue dependency so rebuilding bundles does not pick up incompatible upstream releases.
- Dual-websocket sessions wait for both sockets before becoming ready, so an early initialization report cannot strand queued updates.
- Server shutdown and precompile cleanup explicitly close and join the session cleanup timer, instead of leaving a sleeping task pending at process exit (#430).
- Server-side DOM updates preserve a disconnected page's reconnect grace period instead of treating it as a page that never connected. A failed websocket write also leaves the session eligible for soft-close cleanup.
- Mobile pages replace stalled websocket handshakes and keep retrying while visible after the initial retry window ends; network-online and page-resume events trigger recovery too.
- A browser that stops reading its websocket (a frozen phone tab) no longer stalls every websocket upgrade on the server: `isopen` no longer waits on the lock a blocked send holds, which the session cleanup did while holding the route table.
- A reconnect no longer waits for a send wedged on the dead connection it replaces: after 2 seconds that connection is ended and the message queued for replay. The replaced connection is closed.
- A page whose session the server no longer has stops retrying instead of flapping between "connected" and "connecting": the server closes with 4404 and the page gets the new status `"expired"`.
- A page shown again after the browser froze it (`visibilitychange`, `pageshow`) replaces a socket that stays silent and restarts a retry loop that ran out.
- A websocket closed without a close frame (1006) is no longer logged as an error.
- A sub-session replaced before the browser finished loading it (an Observable updated several times in quick succession) no longer loses its assets while the browser still fetches them: its init payload returned a 404, surfacing as an unhandled promise rejection. A closed sub's asset server now stays open until the browser reports that sub loaded.
- A failed load of a sub-session that is already closed no longer marks the page as failed, so `isready` no longer throws for it.
- An Observable shared by several sub-sessions no longer reads as `null` in one of them ("TrackingOnly: Key K not found in GLOBAL_OBJECT_CACHE"). A sub got only a reference while the page had no copy yet, because the copy sat in a payload of content kept out of the document (a hidden pane, a virtual list). Or the page had already freed it, because the sub holding the copy went away first. A reference is now sent only once the page has read another session's copy, and one the page reads late is pinned for its session.
- Content that is out of the document when its session starts (a virtual-list row, a detached pane) keeps its `onclick` handlers and onload code: node lookups also find the nodes Bonito created that are not in the document.
- `update_session_dom!` whose target is out of the document still waits until the target is back, so content generated by an older Bonito (an eval worker's project) keeps finding its nodes. If Julia closes that session while it waits, the update is dropped instead of starting a session the page already freed.
- Leaving a page no longer reports the payload fetches it aborts as session errors.
- A dropped websocket no longer logs a console error; its close code is logged instead.
- A payload request the server turned away no longer hands the login page it was redirected to to the decoder ("Extra N byte(s) found at buffer[1]"). It fails with "turned away by the server", or waits for `on_refused`.
- Generated CSS classes are named by the rule they carry, so two sessions on one page (a proxied worker app, several apps in a notebook) no longer give one class name two different rules.
- `CSS` keeps its declarations in the order given, and so does `merge` (the second rule's declarations come last). A `Dict` wrote them in hash order, so a rule like `"border" => ..., "border-top-color" => ...` could come out with the shorthand last, and a spinner built that way showed a still grey ring. Nested rules keep their order too. A `CSS` built from a plain `Dict` is taken in sorted order.

## [5.0.0]

The biggest release since the package was renamed from JSServe. Most of the work went into networking, session handling, asset serving and serialization, making communication with the browser substantially faster and more stable. See the [release blog post](https://bonito.sh/dev/v5-release.html) for the full write-up and benchmarks.

### Breaking

- **Requires Julia 1.11** (was 1.10).
- **Now depends on HTTP.jl 2.4** (was 1.x). Any environment or downstream package that pins HTTP to 1.x must upgrade. Code touching HTTP/WebSocket internals through Bonito may need adjusting.
- **Session model rework.** `Session` was split into a `RootSession` (one per real connection) and lightweight per-render sub-sessions, and `SubConnection` was removed. Code that constructed `Session`/`SubConnection` directly, or dispatched on `Session{SubConnection}`, no longer compiles. Use the documented `App`/`Page` API; test for the connection root with the new `isroot(session)`.
- **`isready(session)` no longer force-closes the session on a recorded init/render error.** It still throws that error by default (`throw=true`) to surface the real cause, but now leaves the WebSocket open so the error reaches the browser through the reconnect indicator. The new `throw=false` keyword returns a pure connection-state check without consuming or raising a recorded error. Callers that want the old behavior must `close(session)` explicitly.

### Added

- New `Bonito.DocumenterBonito()` Documenter format: a VitePress-style, fully Bonito-rendered docs site (landing page, sidebar, search, version switcher and an experimental blog with RSS) with no extra static-site generator or Node build.
- `LoadingPage` is now exported.
- `KeyedList` for efficient keyed list rendering.
- Terminal/markdown rendering helpers: `RichText`, `TerminalOutput`, `ANSI_CSS`, `ansi_to_html`, `has_ansi_codes`, `append_html!`, `bonito_parser`, `commonmark_to_dom` (ANSI escapes + CommonMark in terminal output).
- Remote apps: drive an app running in one Julia process from another.
- Dark-mode-aware built-in widgets via `--bonito-widget-*` CSS variables with a `prefers-color-scheme` default mapping.
- HTTP asset server gained range requests for media, `Cache-Control` headers, automatic registration of interpolated ES6 modules, and precompile-time tracking of its source/bundle dependencies.

### Changed

- Object and asset lifetimes are managed with reference counting instead of finalizers (no more finalizers running inside locks).
- App rendering has a single error boundary: render and init errors are caught and surfaced through the reconnect indicator's `error[]` observable and a minimal error page, instead of taking down the session.
- Reactive wrappers no longer break `flex`/`grid` layout when an Observable sits in the middle of a layout.
- Testing and display run on [ElectronCall](https://github.com/IanButterworth/ElectronCall.jl) (the old Electron backend still works).
- Faster serialization via a reusable per-session pack buffer (`SessionIO`) and upstream MsgPack.jl improvements.

### Fixed

- Numerous connect/close and reconnect races, reconnect deadlocks and stale-error reconnects, and thread-safety issues across the session lifecycle.
- `port = 0` (ephemeral port) now works; `proxy_url` fixes.
- msgpack packing scratch buffers (`SessionIO`) are now pooled per session *tree* on the `RootSession` instead of allocated per `Session`. One buffer is checked out per in-flight message and returned afterwards, so idle memory is bounded by concurrency (≈1 buffer) rather than by sub-session count, and the re-entrant pack path no longer allocates a throwaway buffer. A buffer that a one-off large message (e.g. a WGLMakie scene) grew past 1 MiB is dropped back to a small buffer on return, so a long-lived session no longer pins tens of MB of idle packing scratch.
- Fixed an unbounded asset leak on the page root: `push_dependencies!` copied every sub-session's imports into `root.imports` and never released them, so the root pinned each closed sub's `Asset` (and its bundle bytes) for the whole page lifetime. A sub's asset tags live in its own swappable fragment (not the page `<head>`), so they are removed when the sub closes; the root no longer retains them. Asset *serving* remains refcounted by the asset server, which keeps a shared asset available while any holder is open and frees it once the last one closes.
- `Asset` now compares and hashes by value (file path + load mode) instead of object identity, so import de-duplication is consistent with the path-keyed asset server.
